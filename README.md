# 设备借用与权限管理平台

基于 Spring Boot 和 Vue 3 的单体应用，围绕单件设备借用实现申请、审批、领用、归还及取消流程，并接入用户角色授权、JWT 认证、Token 撤销和操作审计。

项目用于 Java 后端学习与实习面试准备。目前已具备首版业务代码、前端界面和虚拟机容器部署，后续继续完善权限维护、使用体验及有证据的性能优化。

## 功能范围

- **认证与退出**：账号密码登录、BCrypt 密码校验、JWT 签发和校验、Redis Token 撤销。
- **设备管理**：按 ID 查询、状态筛选与分页、可借设备列表、设备新增和基本信息修改。
- **借用流程**：提交申请、查看自己的申请、管理员审批或拒绝、本人确认领用、管理员确认归还。
- **取消与超时处理**：待审批或已批准申请主动取消；超时未领用申请自动取消并释放预留设备。
- **用户与角色**：用户分页、启用与禁用、查询用户已有角色、分配与撤销角色；一个用户可拥有多个角色。
- **角色与权限**：后端提供角色目录、全部权限目录、角色已有权限查询，以及角色权限的授予和撤销；对应前端尚待接入。
- **接口授权**：按权限码保护接口，借用人身份从后端登录主体取得；本人操作另行校验资源归属。
- **操作审计**：关键操作的成功与失败记录、操作人和资源信息、角色变更明细、审计日志分页查询。
- **前端页面**：登录、工作台、设备、我的申请、待审批、归还确认、用户角色和审计日志。

现有角色与权限的关联已提供后端维护接口；角色、权限定义本身的新建、修改和删除尚未实现。前端当前仍使用手填角色 ID 的用户角色分配方式，角色目录与角色权限配置界面尚未接入。

## 技术栈与工程结构

- 后端：Java 17、Spring Boot 3.5.16、Maven、MyBatis-Plus 3.5.18、MySQL 8。
- 安全与审计：Spring Security、JWT、Redis、Spring AOP、Spring 事务。
- 前端：Vue 3、Vue Router、Element Plus、Vite、pnpm。
- 部署：Ubuntu Server、Docker、Nginx；本次依赖镜像与配置见部署说明。

## 业务流程与状态

正常申请状态：

~~~text
pending → approved → received → returned
~~~

对应设备状态：

~~~text
available → reserved → borrowed → available
~~~

- 只允许对 available 设备提交申请，提交时申请为 pending，设备暂不占用。
- 管理员批准后，申请变为 approved，设备变为 reserved，并记录审批人、审批时间与应还时间。
- 申请人确认领用后，申请变为 received，设备变为 borrowed。
- 具有确认归还权限的管理员处理后，申请变为 returned，设备恢复 available。
- pending 申请可被拒绝为 rejected。
- pending 或 approved 申请可由本人取消；取消 approved 申请时释放设备预留。
- 超时领取截止时间为审批日期后第二天的上海时间 12:00，并非严格计时 48 小时。
- 取消状态沿用当前代码值 cancel；“已领用”的申请状态是 received，设备状态是 borrowed。

所有状态迁移由后端校验，前端按钮只提供交互提示。

## 关键实现与取舍

### 认证、退出与权限变更

JWT 包含用户身份、过期时间和用于区分 Token 的 jti。退出时，将 jti 写入 Redis 撤销记录，TTL 使用 Token 剩余有效期；后续认证查询撤销状态。

携带有效 Token 的请求还会读取数据库中的账号启用状态和权限集合，写入本次请求的 SecurityContext。因而，禁用用户或修改角色权限后，后续请求会按新状态判断，不依赖 JWT 内固化一份长期有效的权限列表。

该方案优先保证后续请求读取当前权限，代价是增加数据库及 Redis 查询。目前未引入权限缓存。依赖查询异常时返回服务不可用，不将“无法判断是否撤销”视为认证成功。

接口权限与资源归属分别处理：拥有借用接口权限，也不能领用或取消别人的申请。需要权限的 GET 查询同时配置对应 HEAD 授权规则。

### 条件更新与多表事务

审批、领用、归还和已批准申请取消涉及申请表与设备表的关联更新，在 Service 层使用事务管理。

更新时同时限定主键和原状态，例如设备只有处于 available 才能预留、申请只有处于 pending 才能批准。更新行数不符合预期时返回 409 冲突，避免重复推进状态；多表操作发生异常时由事务回滚。

这里的条件更新实现与并发实验结果分别记录，不以代码存在代替并发验收。

### 成功与失败审计

通过自定义审计注解和 AOP 提取动作、操作人、资源及结果，记录关键写操作；部分请求在进入业务方法前失败时，由安全响应或全局异常处理补充失败审计，并按动作去重。

借用状态变更等事务内的成功日志参与业务事务。登录、退出、用户角色变更和角色权限授予/撤销采用独立审计；失败日志在业务事务结束后通过独立事务尝试保存。角色权限变更以角色为资源，明细记录 roleId、permissionId。

独立审计失败会记录服务端错误，不覆盖原业务结果。当前没有异步消息投递或持久化重试队列，不保证数据库不可用期间的审计记录仍能成功入库。审计不保存密码、完整 Token 或任意请求体。

### 超时未领用取消

任务在应用启动时及每天上海时间 12:00 执行，按申请 ID 游标每批读取最多 200 条候选记录，并逐条重新校验状态和领取截止时间后处理。

借用人领取时也校验截止时间；已超时的申请会触发取消流程。定时扫描和请求触发的取消共用事务处理入口，按条件更新处理状态竞争。

运行前需要 MySQL、Redis，以及对应数据库、Redis 密码和 JWT 签名密钥。根据运行环境配置地址，不直接照用他人虚拟机 IP。

- [前端、本地启动及页面接口约定](src/main/resources/frontend/README.md)
- [Docker 构建、数据库迁移、Nginx 与完整部署步骤](deploy/README.md)
- [空数据库初始化脚本](deploy/mysql/001-init.sql)
- [Nginx 配置](deploy/nginx/default.conf)

空库初始化脚本创建 8 张核心表、借用人和管理员两个演示账号、14 项权限、15 条角色权限关联及一台可用设备，不含历史借用和审计数据。借用人拥有 2 项权限，管理员拥有 13 项权限，包含角色权限授予和撤销。演示账号说明见部署文档。

初始化脚本只用于空库。已有环境迁移数据时，不再叠加执行初始化脚本；原有 resources/sql/RBAC.sql 是学习记录，不作为建库入口。

后端打包示例：

~~~powershell
$env:JAVA_HOME = 'C:\Java17'
$env:Path = 'C:\Java17\bin;' + $env:Path
mvn "-DskipTests" package
~~~

前端在 src/main/resources/frontend 中独立执行：

~~~powershell
pnpm install --frozen-lockfile
pnpm build
~~~

打包命令跳过了后端测试，构建成功不代表业务测试通过。实际启动、配置和文件传输按上方对应文档执行。
